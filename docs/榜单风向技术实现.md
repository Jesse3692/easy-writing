# 榜单风向：技术实现细节

> 整理日期：2026-09-29（基于当前代码实测梳理，供后续维护与其他模块借鉴）
> 功能入口：侧边栏「榜单风向」（`src/views/NovelRank/index.vue`）

## 0. 总览

榜单风向是一个**纯本机**的网文榜单抓取/趋势系统，无自建服务端依赖：
数据源配置 → 本机爬虫（含反爬对抗）→ IndexedDB 每日快照 → 本地现算分析/AI 解读 → 页面展示。

```
rank-sources.ts（站点/分类/84 榜单源种子配置）
        │
        ▼
local-rank-store.ts ──频控/模式──► local-rank-crawler.ts（统一入口，按站点分派）
        │                                ├─ 番茄：HTTP 直取 HTML / 隐藏窗口滚动懒加载
        │                                ├─ 七猫：官方 JSON 接口翻页
        │                                └─ 起点：隐藏窗口过 probe.js 反爬 + ttf 字体解码
        ▼                                （桌面端：@tauri-apps/plugin-http、Rust rank_crawl_render_page）
IndexedDB 快照（ew-local-rank，每源每日一份，保留 120 天）
        │
        ▼
local-rank-analysis.ts（分类分布/标签风向/排名变化/竞品/作者趋势/CSV 导出，全部现算）
        │
        ▼
NovelRank/index.vue（榜单表 + 搜书过滤 + 数据分析面板 + AI 趋势解读 + 首页风向偏好）
```

**沿革**：整套功能移植自老服务端（`statistics/service/rank` 的番茄/七猫/起点适配器、
`defaultSeed` 种子数据），本机化时**刻意保持老 HTTP 接口的响应形状**——页面里
`import { getLocalRankLatest as getNovelRankLatestApi } from '@/storage/local-rank-store'`
（`index.vue:606`），接口契约不变、页面零改动消费。平台改版时优先改
`rank-sources.ts` 的 url/选择器与对应适配器，不动存储与页面。

## 1. 数据源配置（`src/config/rank-sources.ts`）

三张静态种子表，带 `legacyId` 保留与老服务端数据库的 id 对应关系：

- **站点**（3 个）：番茄 `fanqienovel.com` / 起点 `www.qidian.com`（备注：隐藏窗口方案过反爬，桌面版）/ 七猫 `www.qimao.com`；
- **分类**（178 个）：`code` 是站点原生分类路径片段（番茄 `1_2_1014` = 男频-阅读榜-都市高武；起点 `chanId21-subCateId8`；七猫 `a-203-219`），支持 `parentLegacyId` 父子层级，`gender` 分男/女频；
- **榜单源**（84 个）：一条 = 一个可抓取的具体榜单 URL，核心字段：
  - `rankType`：`reading`（阅读榜）/ `new`（新书榜）/ `hotsale` / `monthTicket` / `hot` / `collect` / `newauthor`；
  - `meta` 抓取参数：`maxPages` 翻页上限、`pageMode`（起点 `suffix`=拼 `/pageN/`、`segment`=拼 `?page=N`）、`metricName/metricMode`（指标口径：在读/月票/热度）、`scope`（`all` 站点总榜 / `category` 分类榜）、`gender`；
  - 番茄源 URL 即分类榜页 `https://fanqienovel.com/rank/{code}`，每个分类一个源；
  - 七猫源是官方 JSON 接口 `qimaoapi/api/rank/book-list?is_girl=0&rank_type=1&date_type=1&page=1`；
  - 起点源是裸榜单路径（`/rank/hotsales/`、`/rank/yuepiao/`、女频用 `www.qdmm.com`）。

导出若干查询函数（`rankPlatformOptions` / `rankCategoryOptions` / `findRankSource` 等），
页面下拉与爬虫分派都从这里取数。**平台改版时只改这张表和适配器选择器。**

## 2. 爬虫层

### 2.1 运行时分派与通用请求（`local-rank-crawler.ts`）

- 统一入口 `crawlRankSource(source)` 按 `siteCode` 分派三个适配器；
- 桌面端（Tauri）用 `@tauri-apps/plugin-http` 发请求——**可自带 UA/Referer、不受跨域限制**；
  网页端浏览器直连必被 CORS 拦下，直接抛可读错误「榜单抓取是桌面版功能」；
- 所有请求 30 秒超时（AbortController），带浏览器 UA + `Accept-Language: zh-CN` + 站点 Referer；
- 错误信息全部人话化（「目标站返回 HTTP 503」「抓取超时（30 秒无响应）」）。

### 2.2 番茄适配器（HTML 解析）

番茄榜单页是 SSR 首屏（约头部 10-30 名），后续页懒加载。抓取两条路：

1. **多页配置（maxPages>1）且桌面端**：走隐藏窗口滚动懒加载（见 2.5），滚动轮数
   `min(max(maxPages*6, 6), 30)`；失败则 `console.warn` 后**退回首屏直取**（宁少勿断）；
2. **首屏直取**：plugin-http 拉 HTML → `DOMParser` 解析（选择器与老 cheerio 实现一致：
   `.muye-rank-book-list .rank-book-item`，名次/涨跌/书名/作者/封面/简介/在读/最新章节各有专属选择器）。

解析细节：

- **封面兜底**：从页面脚本里抠 `window.__INITIAL_STATE__ = {...}`（`extractAssignedJson`：
  字符串感知的括号配平，不会被 JSON 内的引号/括号骗到）取高清 `thumbUri`，失败退 `<img>` 的
  `src`/`data-src`，并优先 `fqnovelpic.com/novel-pic/` 真图、过滤 `novel-static` 占位图；
- **字体反爬解码**：番茄把正文渲染成**私用区（PUA，U+E000–U+F8FF）码点**，真实字符靠
  @font-face 决定。解码用静态字典 `config/fanqie-font-dict.ts`（368 行，码点→字符映射，
  移植自老服务端，含 0-9/a-z/A-Z 等）逐字符替换；
- **乱码熔断**：解析后统计书名里残留的 PUA 字符，条目 ≥3 且乱码占比 >50% 时**直接抛错不入库**——
  说明番茄换了字体、静态字典失效，报错可以保住库里上一份好快照（继承老服务端同款保护）；
- 条目不带分类，从源配置反补 `categoryName`（番茄每个分类一个源）。

### 2.3 七猫适配器（JSON 接口）

- 官方接口 `qimaoapi/api/rank/book-list`，按 `meta.maxPages`（≤5）翻页；
- **日榜快照防写旧**：`date_type=1`（日榜）时清掉 `date` 参数用实时榜；
- 每页随机间隔 `600 + rand(500)` ms；`bookId/bookUrl` 去重后重新连续编号；
- 字段直映射：`index_change + surge_rank` 合成名次变动、`number + unit`（万/亿）折算热度值、
  `is_over==1` → 已完结、`latest_chapter_id` 拼章节 URL。

### 2.4 起点适配器（反爬最重）

起点全站有 **probe.js 探针反爬**，普通 HTTP 只能拿到拦截页。方案：

- **隐藏窗口抓取**（2.5）：真实 WebView 环境自然通过探针，cookie 由窗口会话自持；
- 逐页抓（`/rank/yuepiao/` → `/rank/yuepiao/page2/`，`buildQidianPagedUrl` 拼接），页间隔
  `900 + rand(600)` ms，去重合并；首页失败整体报错，后续页失败用已拿到的部分；
- **月票数字是动态字体反爬**：数字用非常规 Unicode 码点渲染，真实字形由页面下发的 ttf 决定。
  解码不走静态字典，而是**当场解析 ttf**（`utils/qidian-font.ts`，自实现最小 TTF 解析器，不引字体库）：
  1. 从页面 CSS 抠 `@font-face` 的 `.ttf` 地址（正则匹配 `url(...ttf...) format('truetype')`）；
  2. **只信起点自家 CDN**（`qdfepccdn.qidian.com`，协议 https + 域名白名单），防页面内容导去别处；
  3. 解析 ttf 表目录 → **cmap**（format 12 优先、format 4 兜底——混淆字符多在增补平面）把码点映射到
     glyphId → **post 表 format 2.0** 取 glyph 名（`zero/one/.../nine/period`，内置 258 个标准 Mac
     glyph 名表保证 nameIndex 对位）→ 得到 码点→数字 映射；
  4. 只对页面实际出现的码点求映射；字体拿不到只损失月票数字，条目照常入库（降级不失败）；
  5. `metricText` 为映射解码结果；映射为空时**清掉混淆原文，绝不展示乱码**。

### 2.5 隐藏窗口抓取（Rust 命令 `rank_crawl_render_page`）

前端封装 `local-rank-window.ts`，实现在 `src-tauri/src/lib.rs:746`：

- **安全约束**：仅 https；**host 白名单**（番茄/起点/qdmm/七猫六个域，防该命令被用来打开任意网页）；
  超时默认 60s 上限 180s；滚动轮数上限 40；
- 流程：`WebviewWindowBuilder` 开一个**不可见**（`visible(false)` + skip_taskbar）的 1280×900 窗口
  加载目标页 → 注入 `initialization_script`（一段纯 JS 状态机）：
  1. 每 500ms 轮询 `waitSelector` 是否出现（页面就绪标志）；
  2. 就绪后等 600ms 让首屏渲染完整；若 `scrollRounds>0` 进入滚动循环：
     `scrollBy` 一屏 → 800+rand(400)ms 后数选择器数量，**连续 2 轮数量不涨即认为加载完**（稳定判定），
     最多滚 `scrollRounds` 轮；
  3. `document.documentElement.outerHTML` 通过 Tauri 事件（`plugin:event|emit`，每抓取一个
     唯一事件名防串扰）回传 Rust；
- Rust 侧 `tokio::time::timeout` 等事件，拿到 HTML 后销毁窗口、解析 payload 返回给前端；
  超时给可读错误「榜单页面加载超时（可能被站点限制或网络不稳）」。

番茄懒加载、起点探针都靠这一套窗口方案；番茄 SSR 首屏直取失败时也退到这里。

## 3. 存储层（`local-rank-store.ts`）

- **IndexedDB**：库名 `ew-local-rank`，单 kv store。快照键 `snap:{sourceId}:{YYYY-MM-DD}`，
  值 = `{sourceId, statDate, fetchedAt, pageTitle?, cutoffText?, items[]}`；
- **三档抓取模式**（页面右上角切换）：
  - `off`：不发任何请求，只展示已有本机数据；
  - `manual`（默认）：点「抓取本榜」才抓；
  - `auto`：**每天自动补抓「最近看过的榜单」**——浏览榜单时记录 `viewedSourceIds`（去重保序上限 12），
    auto 模式每天首次触发时抓其中前 6 个（`AUTO_CRAWL_MAX_SOURCES`），逐源间隔 1.2+rand(0.8)s、
    静默容错，结果写 `lastAutoSummary`。应用打开期间在页面挂载/切模式时触发（`index.vue:2122`）；
- **频控**：每源每日一份快照；当日已有快照时，非手动请求直接复用，手动重抓 30 分钟内
  走缓存并提示「半小时内已抓取过」（`MANUAL_RECRAWL_MIN_MS`）；
- **保留策略**：快照保留最近 **120 天**，抓取后 `pruneSnapshots` 清理过期键；
- **趋势靠日积月累**：`attachCompare` 把当前快照与上一份快照（显式对照日期或严格早于当前的
  最近一份）按 `bookId || bookTitle` 配对，补差值字段 `prevRankNo / rankChangeDelta（升=正）/
  prevMetricValue / metricDelta`；
- **查询口径**：`getLocalRankLatest`（单源，支持 statDate/compareDate/keyword/categoryCode/分页）
  与 `getLocalRankLatestAll`（站点聚合：全部源最新快照合并去重、按指标值重排名）；
  分类过滤是「种子表 code → 分类名 → 与条目 categoryName 精确匹配」，code 查不到时**返回空列表
  如实呈现无数据，不静默回退全量**。

## 4. 分析层（`local-rank-analysis.ts`，全部从本机快照现算）

| 分析 | 口径 |
|---|---|
| 分类分布 | 站点全部源最新快照按分类计数 + 占比，降序 |
| 标签风向 | 近 N 天（2-60，默认 7）每日各源合并，按**二级分类（无则一级）**逐日计数，总量 Top N（默认 6，≤12）出趋势线。起点条目自带二级分类喂出来最细，番茄/七猫退化为分类热度 |
| 排名变化 | 单源当日 vs 对照快照，按涨跌幅绝对值 Top N |
| 竞品对比 | 指定 bookIds（逗号分隔）近 N 天（默认 14，≤60）逐日名次/指标序列，缺日为 null；同书同日多源取最好名次 |
| 作者趋势 | 指定作者近 N 天逐日在榜本数 / 指标合计 / 均值 |
| 导出 | 服务端 xlsx → 本机 **CSV**（带 BOM 让 Excel 正确识别 UTF-8），单源或站点聚合，上限 1000 条 |

「每日合并」的公共口径 `mergedDayItems`：站点所有启用源在指定日期的快照合并成
`Map<bookId|bookTitle, item>`，同书取最好名次——**榜单数据攒得越多，趋势线越有料**。

## 5. AI 趋势解读（数据分析面板的「AI 解读」）

- 不引入独立模型调用链：把**当前表格 Top20（书名/作者/分类/指标/名次变动）+ 排名变化 Top10 +
  分类占比 Top8** 拼成三段文本素材（`buildAiReportLines`），走通用
  `requestLocalChatCompletion`（`scene: 'rank_report'`），用用户自己配置的文本模型；
- 提示词在本地提示词库 `rank-report`（`config/prompts/defaults-misc.ts:92`，用户可改）：
  > 只依据给到的数据说话，数据没体现的不要编造。用大白话输出 300 字以内，分三段：
  > 榜单格局 / 变动信号 / 给作者的建议。没有对照数据时如实说明「暂无变化数据，攒几天快照后更准」。

## 6. 展示层（`views/NovelRank/index.vue`，约 3200 行）

- **筛选区**：平台 Tab（番茄/起点/七猫）→ 榜单类型（阅读榜/新书榜）→ 性别（男频/女频）→
  主题分类（番茄为分类榜源；起点/七猫为站点总榜 + 分类后过滤）；统计日期（快照日）+
  对照日期（默认上一份快照）驱动「在读变化」列；
- **「全部分类」聚合视图**：番茄无站点总榜，前端把全部源快照合并（`getLocalRankLatestAll`）；
  起点等有原生总榜（`scope=all`）则直接取该源，避免错误聚合；
- **搜书**：输入作者名或作品名，回车/点搜索后以 `keyword` 参数走本地快照过滤
  （书名/作者/分类包含匹配，见 `filterKeyword`）——**不是调站点搜索接口**；
  「没找到我的作品，去反馈」跳反馈页；
- **抓取本榜**：需选中具体分类源（番茄聚合视图提示先选分类），调 `crawlLocalRankSource(manual)`
  → 成功后刷新列表与分析面板；模式切换（关/手动/自动）即时持久化；
- **数据分析面板**：分类分布（饼图）、标签风向（多折线）、排名变化、竞品对比、作者趋势，
  图表用 ECharts（`utils/echarts.ts`），数据全部来自第 4 节本地现算；
- **设为首页风向**：把当前筛选（平台/榜单类型/性别/分类）存为 `homePreference`（本地设置），
  首页按它展示风向卡片；
- **导出数据**：第 4 节的 CSV 导出（Blob 下载）。

## 7. 值得记取的设计点（供其他模块借鉴）

1. **老接口契约本机化**：本地函数用 `as getNovelRankLatestApi` 别名顶替原 HTTP API，
   页面零改动完成服务端 → 本机迁移；拆书（breakdown）模块同款打法。
2. **抓取失败保旧数据**：番茄乱码熔断、起点后续页失败用部分结果——**任何情况下不损坏库里
   已有的好快照**，错误一律人话化上抛。
3. **反爬两板斧对应两类字体**：静态字典（番茄 PUA）便宜但要跟版本；动态解析字体文件
   （起点 ttf 的 cmap+post）一次实现永久有效，且「只信自家 CDN」「解码失败降级不失败」。
4. **隐藏窗口是万能兜底**：probe.js 探针、懒加载、cookie 会话全部由真实 WebView 自然解决，
   Rust 侧只做白名单 + 超时 + 注入滚动脚本三件事。
5. **频控在存储层**：每源每日一份快照 + 手动 30 分钟冷却 + auto 模式每日补抓常看榜单——
   「用户用自己的网络为自己抓公开数据」，抓取节奏温和（翻页随机间隔、每日上限）。
6. **快照即趋势**：不做增量同步，每日快照 + 本地现算出五类分析，数据攒得越多越准。
