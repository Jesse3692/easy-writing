## 0. 总览

一句话：**全部 AI 提示词以 markdown 文件形式存在本地，用户可改；代码里只保留槽位结构与默认文本**。
设置页可视化编辑和用户直接改 md 文件操作的是同一份内容——「提示词即文件」。

```
config/prompts/（代码侧：结构定义 + 默认文本，只读）
  types.ts            PromptFileDef / PromptSlotDef 结构

  defaults-workflow.ts 工作流建书 2 组

        ▼

        │ 双通道持久化
```

## 1. 数据模型（`config/prompts/types.ts`）

两层结构，**代码只认槽位结构，不硬编码提示词文本**：

- `PromptFileDef`：`{ id, name, group, description, slots[] }`
  - `id` 是稳定标识，写进 md frontmatter——**文件被用户改名也能对上号**；
  - `name` 兼作 md 文件名（`{name}.md`）与界面场景名；
- `PromptSlotDef`：`{ key, label, variables?, defaultText, defaultTemperature? }`
  - `key`：代码取文本用的稳定标识（如 `system` / `chapterShape` / `goldenNote`）；
  - `label`：md 里的 `## 段名`，也是编辑界面的字段名；
  - `variables`：该槽支持的 `{{变量}}` 清单，展示给用户（空 = 纯文本原样使用）；
  - `defaultText`：默认文本，仅用于首次生成 md 与「恢复默认」；
  - `defaultTemperature`：槽级采样温度（0-2），数值沿用老服务端逐场景调优
    （如打字补全 inline 0.3/next_beat 0.85、剧情分析 0.1、拆书/榜单解读不定义 = 用模型默认）；
    **未定义 = 该场景不调温**。

**JSON 输出契约（形状）也放进 md**：如拆书的 `chapterShape` 槽存的就是期望 JSON 结构说明——
形状对用户可见可改；改坏了导致解析失败，删掉该 md 文件即恢复默认。

## 2. md 文件格式（`serializePromptFile` / `parsePromptFile`）

```markdown
---
id: breakdown
---

> 竞品拆书 —— 单章拆解、黄金三章深拆与全书报告
> 按 "## 段名" 分段编辑，段名不要改；改坏了删掉这个文件即可恢复默认。
> 「系统」里的 {{JSON形状}}、{{补充要求}} 是程序代入的内容，请保留。
> 段首的「温度：x」是该段调用模型的采样温度（0-2，越低越稳、越高越发散），可改数值，别删这一行。

## 系统

温度：0.7

你是一个网文拆书助手……（正文，含 {{JSON形状}} 占位符）

## 单章拆解形状

{"summary":"…","outline":[{"title","startPara","endPara","text","tags":[…]}], …}
```

序列化/解析的要点：

- frontmatter 只记 `id`（正则 `(?:^|\n)id:\s*([\w-]+)` 提取）；
- 正文按 `^## 段名` 切段（`matchAll` + 相邻标题定位区间），段名映射回槽 `label`；
- 段首「温度：x」行（兼容全/半角冒号）剥出来单独存 `tempCache`，**不进提示词文本**；
- 温度钳制到 [0,2] 并保留两位小数；
- 未知段名忽略、缺失段回默认——用户加自定义段不会炸，删段即回默认。

## 3. 存储双通道（`storage/local-prompts.ts` + Rust）

| 端 | 介质 | 说明 |
|---|---|---|
| 桌面端 | `~/Documents/易创提示词/*.md` | Rust 五个命令：`get_prompt_dir` / `list_prompt_documents` / `ensure_prompt_document` / `write_prompt_document` / `open_prompt_dir`（`lib.rs:549-640`） |
| 网页端 | IndexedDB `ew-local-prompts` | 存 md 全文，键 = 文件 id，格式与文件完全一致（开发/预览用） |

Rust 侧的防御细节：

- 目录自动创建（`ensure_prompt_dir`）；
- `list` 只收 `.md`，**单文件容错**（某个文件编码/占用读不出就跳过，不挡整个目录）；
- `ensure_prompt_document` 用 `OpenOptions::create_new(true)`——**只创建缺失文件，
  绝不覆盖已存在文件**（返回 false 表示文件已在但无法识别，前端 console.warn 提示原文件未覆盖）；
- 文件名经 `sanitize_segment` 清洗 + 必须 `.md` 后缀校验，防路径逃逸。

前端装载（`initLocalPrompts`，**在 `main.ts:46` 于 `app.mount` 之前 await 完成**——组装器是
同步读缓存，必须先就绪）：

1. 读目录全部 md → 解析出 `{id, sections}` → 按 id 对号入座写进缓存；
2. 某场景的文件缺失 → 内存用默认值 + 调 `ensure_prompt_document` 补写默认 md
   （删文件 = 恢复该场景默认，就是这个机制）；
3. 整个装载失败（如目录权限）→ 保留已加载的自定义内容，仅为未加载的组补默认值，不阻塞启动。

## 4. 运行时读取（组装器 API）

三个同步函数，全部先查缓存、未命中回默认值：

```ts
promptText(fileId, slotKey)                    // 取文本：用户改过取改过的，否则默认
renderPromptText(fileId, slotKey, vars)        // 取文本 + 代入 {{变量}}（未提供的变量替换为空）
promptTemperature(fileId, slotKey)             // 取槽温度：无定义 = undefined（不调温）
```

- `{{变量}}` 替换：`/\{\{([^{}]+)\}\}/g`，变量名 trim 后匹配；
- **空槽回退默认**：用户把某段删空，运行时取到的是默认值——不会把空提示词发给模型；
- 另有三个界面辅助：`getLocalPromptSlots` / `getLocalPromptTemps`（当前生效值）、
  `isPromptFileModified`（任一槽文本或温度偏离默认 → 界面标「已修改」徽标）。

消费方式见 `config/ai-prompts.ts`：组装器只负责把动态素材（正文、选中文本、参数）代入
用户可编辑的模板——例如 `renderPromptText('structured-analysis', 'system', { JSON形状: shape })`、
`renderPromptText('editor-selection', 'custom', { 指令 })`、
`promptTemperature('editor-autocomplete', 'inline')`。

## 5. 用户编辑三通道

1. **设置页可视化编辑**（`views/Prompts/index.vue`）：按分组折叠展示 14 个场景 →
   展开列出槽位（变量提示 + 温度滑杆 + 两行预览）→ 点预览弹窗大文本编辑 → 保存即写回 md 并刷缓存
   （「已保存，立即生效」）；温度滑杆 change 即保存；「恢复默认」= 用默认值重写整个 md；
   桌面端显示目录路径 + 「打开文件夹」按钮；
2. **直接改 md 文件**：任何编辑器改 `Documents/易创提示词/` 下的文件，重启应用后生效
   （启动装载读文件）；页面文案明确告知这一双向关系；
3. **删文件 = 恢复默认**：下次启动自动补写默认 md（`ensure` 的 create_new 机制）。

## 6. 旧默认值自动升级（`legacy-defaults.ts`）

2026-08-30 老服务端提示词全量回迁后默认值整体换代，用户目录里可能躺着按**旧默认值**生成、
但从未被用户修改过的 md 段落。处理：

- 离线脚本把旧 defaults 的每个 `defaultText.trim()` 做 **djb2 哈希**（base36），共 68 个指纹
  存进 `LEGACY_PROMPT_TEXT_HASHES`；
- 装载解析时，段落文本命中指纹 → 视为「未修改」，**自动升级为新默认值**；
- 用户真正改过的文本哈希不命中，原样保留。

这让默认提示词可以随版本迭代换代，而不需要用户手动重置。

## 8. 值得记取的设计点（供其他模块借鉴）

1. **「提示词即文件」**：默认值在代码（保证新装可用），真身在用户目录（保证可改可带走），
   结构在槽位定义（保证代码引用稳定）。三者通过 id + label 对齐，改名的文件也不失效。
2. **create_new 而非覆盖**：补默认文件永不覆盖用户文件；「删文件 = 恢复默认」是最直观的
   恢复语义，且天然支持单场景粒度。
3. **空槽回退**：允许用户清空任何槽位而不产生「空提示词发给模型」的故障。
4. **指纹升级**：用文本哈希区分「旧默认值」与「用户修改」，默认文案换代不践踏用户定制——
   任何「内置默认 + 用户可改」的配置体系都可复用这招。
5. **温度进 md**：采样温度属于提示词工程的一部分，跟文本放同一个文件、同一个分段，
   界面滑杆与文件双向同步。
6. **装载时序**：同步读缓存的模块，必须在 app.mount 前 await 装载（main.ts 的注释明确写了
   这个约束）。
