# 工作流建书：技术实现细节

> 整理日期：2026-09-29（基于当前代码梳理，供后续维护与其他模块借鉴）
> 功能入口：侧边栏「工作流建书」（`src/views/WorkflowBook/index.vue`，1793 行）

## 0. 总览

「从灵感到正文的一站式建书流程」，向导四步：
**① 创作方向与灵感**（平台/读者/类型/风格标签 + 灵感输入 + AI 灵感辅助）→
**② 写作参数**（字数/主角/人称等，补全编辑与笔法）→
**③ 生成大纲**（书名候选/简介/钩子/世界观要点/分卷/首卷章纲）→
**④ 生成设定**（世界观卡/核心体系/角色/故事线）→ 确认后落地成一本真实的书并进入逐章自动生文。

```
index.vue（向导编排：草稿 draft + 步骤状态机）
   │ workflow-adapter.ts（run ↔ UI 模型双向映射，兼容老服务端契约）
   ▼
local-workflow-engine.ts（步骤引擎：提交即返回 running 任务，后台执行）
   │ 提示词：config/prompts workflow-wizard（灵感/大纲/设定/调整）
   │ 组装：buildStructuredJsonMessages（素材块 + JSON 形状）→ 本地模型
   ▼
local-workflow.ts（IndexedDB ew-local-workflow：run:* / task:*）
   │ 轮询 getLocalWorkflowTaskStatus（页面 2.5s 一次）
   ▼
大纲/设定产物落 run.artifacts + summary ──确认──► local-workflow-book.ts（建真实书/卷/章/参考库）
```

沿革：替代旧服务端 `/writing/workflow/*` 通道。**run 采用"保存载荷透传"**——前端
`workflow-adapter` 的 config/summary 双向映射一行不改，只换存储与执行引擎。

## 1. 存储层（`storage/local-workflow.ts`）

- **IndexedDB**：库名 `ew-local-workflow`，单 kv store，两种键：`run:{id}`（工作流）、
  `task:{id}`（生成任务）；
- **LocalWorkflowRun** = 服务端 `WorkflowRun` 契约 + 本地扩展字段：
  - `config`（写作参数）/ `summary`（各步产物：ideaText、workflowOutlineUi、workflowSettingUi…）
    **全量透传落库、原样返回**——这是"页面零改动"的关键；
  - `draftRevision`（每次保存 +1）/ `outlineRevision`（大纲产物每次 +1）双版本号；
  - `latestStepTaskId`（向导步骤任务）/ `latestBookTaskId`（逐章生文任务）；
  - `adjustCandidates`：调整候选暂存（candidateId → 完整内容），应用/废弃后移除；
- **生命周期**：`create`（draft 状态）/ `save`（载荷透传 + 版本 +1）/ `info` / `delete`；
  本地单机无并发，**保存即推进版本、不做冲突拒绝**（冲突检查留给界面层对提交_revision 的预期）；
- **删除保护**：run 还有活跃生成任务时拒绝删除；删除时连带清掉名下全部 task 记录；
- **孤儿修复**（`readRepairedLocalTask`）：任务读取时若无活循环（应用中途关过页面）——
  `queued/running` 翻成 `interrupted`（`interruptedReason: 'app_closed'`，提示"已生成内容已保留，
  可继续生成"）；旧整书任务残留的操作锁标记也一并修复。**本地引擎随页面存亡，如实呈现。**

## 2. 向导编排（`views/WorkflowBook/index.vue`）

### 2.1 草稿与惰性落库

- 页面维护一个响应式 `draft`（方向/灵感/参数/大纲/设定全在内存），
  `workflow-adapter.ts` 负责 run ↔ draft 的双向映射（`applyWorkflowRunToDraft` /
  `buildWorkflowSavePayload`）与产物规范化（`normalizeOutlineResult` / `normalizeSettingResult`）；
- **惰性建 run**：`ensureWorkflowRun` 只在首个实质动作（生成灵感/采用灵感/下一步/保存）时
  真正 `createWorkflowApi`；**没 run 也没写过灵感时不落库**——点一下历史/模板库不会产生空记录；
- **persistDraft**：先 ensure 再 save，带 `expectedDraftRevision` 提交；冲突时弹窗让用户选
  「加载服务端版本」或「用本地草稿覆盖」，每次覆盖都需用户显式点击；
- **模型语义**：`modelCode` 空 = 跟随默认（模型管理页的建书默认模型）；草稿里的模型下架时
  回落「跟随默认」而非悄悄换另一个；活动 run id 挂在 0 号桶（开源版单用户）。

### 2.2 四步状态机（`handlePrimary`）

步骤常量即存储里的 `currentStep`：`MODE_SELECT → BASE_CONFIG → OUTLINE_GENERATE → SETTING_GENERATE`。

| 当前步 | 「下一步」动作 |
|---|---|
| ① MODE_SELECT | 校验方向与灵感非空 → `syncAutoSellingPoint`（核心卖点自动带入）→ 持久化后进入 ② |
| ② BASE_CONFIG | 分类校验 → 已有大纲先确认覆盖 → `runStepTask('outline')` → 规范化落 draft → 进入 ③ |
| ③ OUTLINE_GENERATE | 已有设定先确认覆盖 → `runStepTask('setting')` → 进入 ④ |
| ④ SETTING_GENERATE（末步） | `pruneUntouchedSettingEntries` 清掉"新增了却没填"的空行（空白条目进提示词会被模型当"存在但没写清"硬圆，拖累质量）→ 确认弹窗 → `enterAutoWriting` |

### 2.3 步骤任务提交与轮询

`runStepTask(step, input, saveOverride)`：

1. 先 `persistDraft` 保存当前草稿（拿 `draftRevision`）；
2. `submitWorkflowStepTaskApi({ runId, step, expectedDraftRevision, input })` 提交——**立即返回
   running 任务**；提交前后再冲突则走「重建唯一草稿真源再提交」的覆盖链；
3. `waitStepTask`：2.5s 轮询任务状态（网络抖动/5xx 放慢到 4s 续轮），校验
   `payload.step === requestedStep`（**步骤不一致拒绝消费结果**），直到 `succeeded / canceled /
   failed / interrupted`；组件卸载只停轮询，任务在后台跑完落终态；
4. 「停止生成」= 任务取消（AbortController 真正掐掉在途模型请求），已完成子步骤结果保留；
5. 失败时 `recordStepFailure` 记录步骤上下文，错误条上可直接「重试」（重放同参数）。

## 3. 步骤引擎（`utils/local-workflow-engine.ts`）

`submitLocalWorkflowStepTask` 是全部五种步骤的统一入口（灵感/大纲/设定/大纲调整/设定调整）：

- 立即写一条 `running` 任务落库并返回，真实生成在本进程**后台异步执行**；
- `registerLiveLocalTask` 登记活任务（取消 = `abort.abort()` + 置 cancelRequested）；
- 终态（`succeeded` 带结果 / `canceled` / `failed` 带人话错误）写回任务记录，等轮询取走；
- **模型解析**：`run.modelCode`（或 config.modelCode）显式指定优先，否则 `ensureTextModel()`
  取建书默认模型；
- **素材组装**：`describeBaseConfig` 把写作参数拼成「平台/题材/分类/标签/书名意向/目标字数/
  单章字数/主角/叙事人称/目标读者/核心卖点」的标签行文本，作为【写作参数】材料块进提示词。

三个生成步骤的输入输出：

| 步骤 | 材料来源 | 校验（解析失败即人话报错） |
|---|---|---|
| inspiration | 创作方向 + 作者的想法 + 写作参数 | `ideaText` 非空；解析失败兜底取全文 |
| outline | 写作参数 + **run.summary.ideaText**（灵感步产物） | `chapters` 或 `volumes` 数组存在 |
| setting | 写作参数 + **大纲底稿**（简介/钩子/世界观要点/分卷概述拼文本） | `characters` 或 `worldCards` 数组存在 |

解析失败统一走 `describeUnparsableResult`：**把模型返回的开头 80 字带进错误文案**——
用户一眼能看出是空、是截断还是答非所问。大纲/设定用 `LONG_COMPLETION_TIMEOUT_MS` 长超时。

## 4. 提示词（`workflow-wizard`，用户可在提示词页改）

四个 JSON 形状槽 + 任务槽全部在本地提示词库（`defaults-workflow.ts`）：

- **灵感**：`inspirationExpand`（把想法扩成完整灵感）/ `inspirationRandom`（AI 先抛一个）+
  内容要求（200 字内：一句核心设定 + 主角处境 + 核心冲突 + 爽点方向）+ `ideaShape`；
- **大纲** `outlineShape`：`titleOptions`（3 个候选书名 + selectedTitleId）、`intro`（120-200 字简介）、
  `storyHook`（贯穿全书的核心钩子）、`worldItems`（3-6 条世界观要点）、`volumes`（2-3 卷，
  每卷含**阶段 stages**：目标/起点状态/终点状态/必须发生/不允许发生/允许引入的新元素）、
  `chapters`（首卷开头 6-10 章的章名 + 80-150 字章纲）、`infoItems`/`suggestions`；
- **设定** `settingShape`：`worldCards`（4-6 张世界背景卡）、`core`（力量体系含 4-8 境界 +
  能力/机制/资源体系）、`characters`（4-8 个角色：身份/背景/关键词/动机）、`storylines`（3-5 条故事线）；
  图标一律 FontAwesome 类名（UI 直接渲染）；
- **调整规则** `outlineAdjustNote` / `settingAdjustNote`：「调整范围之外的内容原样保留
  （**包括 id**），输出完整 JSON」——保证调整不破坏未提及部分与前端按 id 的增量比对。

任务描述里的数量约束（3 个书名、2-3 卷、6-10 章、4-8 角色）全部写死在默认提示词文本里，
改提示词即改生成规模，无需动代码。

## 5. 「按要求调整」：候选账模式

大纲/设定生成后，页面的「AI 修改」抽屉支持定向调整（`WorkflowOutlineAdjustDrawer` /
`WorkflowSettingAdjustDrawer`）：

- **范围（scope）**：大纲 = 整份/书名/核心钩子/世界观要点/分卷规划；设定 = 整套/世界背景卡/
  核心体系/角色/故事线/指定角色/指定故事线（带 `targetId`）；
- **保留（preserve）**：书名/钩子/世界观要点/卷数；角色数量/主角/力量境界/世界规则——
  以中文标签拼进提示词「必须保持不变：…」；
- **四阶段进度**：`read → preserve → generate → verify`（10% → 35% → 85% → 100%）写进任务
  payload 的 `adjustProgress`，由现有轮询带回，**不额外开推送通道**；
- **变更摘要**：本地 diff 前后两份 JSON（`diffOutlineChanges` / `diffSettingChanges`），
  产出 `{key, label, before, after}[]` 给抽屉做对比展示；
- **候选账**：调整结果不直接生效——暂存到 `run.adjustCandidates`，抽屉里「应用」=
  `consumeAdjustCandidate` 取出 → `applyArtifactToLocalRun` 落为新产物并推进版本
  （大纲产物推进 `outlineRevision`）；「废弃」= 取出即弃。设定与大纲对不上时返回软警告
  （warnings），**不阻断应用**。

## 6. AI 灵感辅助（步骤①的三个按钮）

- **扩展成灵感 / 随机来一个**：`generateInspiration({ action, directions, ideaText })` →
  引擎按 action 选 `inspirationExpand` / `inspirationRandom` 任务文案；
- **结果先预览再采用**：AI 产物进 `pendingIdeaPreview` 卡片，用户点「采用」才覆盖
  `draft.ideaText` 并持久化——与灵感页「每日推荐」同款"AI 结果不直接落库"闭环；
- **按当前定位生成灵感 / AI 优化**：同样走 inspiration 步骤（带当前方向与半成品文本）；
- 失败记录请求上下文（action/directions/ideaText），错误条「重试」原样重放。

## 7. 落地建书（`utils/local-workflow-book.ts`）

第④步确认后 `enterAutoWriting` → `generateWorkflowBookApi({ runId })`，把向导产物翻译成真实书：

- **书**：选中书名 + 简介 + 题材标签，`globalInstruction` 记 `{ workflowRunId }` 建立关联；
- **卷**：大纲分卷原样建卷，阶段/目标章数等规划参数存卷 `planMeta`；
- **章**：首卷章纲落成真实章节（正文空、`workflowStatus=incomplete`），逐章引擎按序填正文；
- **参考库**：设定的角色 → 参考面板人物卡（第一个角色 role=主角），世界卡/力量体系/能力体系 →
  世界设定条目（type 映射：0 地理 1 势力 2 功法技能 4 等级体系 5 其他），故事线 → 故事线面板；
  **写作台右栏开箱即用**；
- 「100万字」这类中文数字串 `parseChineseWordTarget` 折算数值；
- 只在 run 尚未建过书时执行；之后流程移交写作页（`/writing/{bookId}?from=workflow`），
  活动 run 标记清除，不再作为"进行中的工作流"恢复。

逐章自动生文（章纲规划 → 细纲展开 → 正文流式 → 质检/重写）是独立引擎
（`local-workflow-control.ts` 626 行 + `local-workflow-writer.ts` 981 行，提示词在
`workflow-writer`），不在本文档展开。

## 9. 边界与已知限制

- **全量备份不含工作流 run**：备份 zip 覆盖 library/writing/local-storage/fonts/prompts，
  `ew-local-workflow`（IndexedDB）的 run/任务不在其中——建到一半的工作流目前不随备份走；
- 本地单机无并发，保存即推进版本不做冲突拒绝；版本冲突检查只在「提交任务时对不上预期版本」
  这条链上做；
- 步骤任务随页面存亡：中途关应用 → 任务如实翻 `interrupted`（不是假装后台还在跑）。

## 10. 值得记取的设计点（供其他模块借鉴）

1. **载荷透传本机化**：config/summary 全量落库原样返回，adapter 双向映射零改动——
   服务端 API 换本地引擎的最省事路径（与榜单/拆书同款打法）。
2. **提交即返回 + 轮询终态**：任务先落库再后台跑，页面统一 2.5s 轮询——不开推送通道，
   连调整进度也塞进任务 payload 搭车。
3. **孤儿修复如实呈现**：读任务时发现没有活循环就翻 interrupted，不假装还在跑；
   「已生成内容已保留，可继续生成」。
4. **候选账**：AI 调整不直接生效，暂存候选 + 本地 diff（before/after）+ 用户显式应用/废弃——
   可控生成的标准范式。
5. **步骤校验拒绝消费**：轮询回来的结果先验 `payload.step` 与请求一致，防串台。
6. **空白条目拦截**：落库前清掉"新增了却没填"的行，防止模型把空条目当事实硬圆。
7. **数量约束写在提示词里**：生成规模（几卷几章几个角色）是提示词槽位的一部分，
   用户改文本即改规模。
